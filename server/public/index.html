Pocketful is an iPhone pass designer backed by your own signing server. Your certificates stay private, your designs stay yours, and Wallet gets a real signed pass.

How it works

The app handles design. The server handles identity. Apple Wallet handles the final handoff.

01 Design on iPhone

Choose a pass style, fields, colors, barcode, and artwork.

02 Sign on your server

The API validates the spec and signs a .pkpass in memory.

03 Add to Wallet

The app downloads the pass and opens Apple’s native add sheet.

Quick start

Pocketful is intentionally self-hosted. You bring the Apple signing identity and deploy one small Node service.

  • Paid Apple Developer account
  • Pass Type ID and certificate
  • macOS with Xcode 27+
  • iPhone running iOS 27+
  1. Create your Pass Type ID. Generate the pass certificate in the Apple Developer portal.
  2. Deploy the signing server. Set the certificate, team, pass type, and API token environment variables.
  3. Build the iPhone app. Select your signing team in Xcode and run Pocketful on a physical device.
  4. Point the app at your server. Enter its URL and API token under Advanced → Server, then create a pass.
Certificates need a few exact steps. Follow the complete setup guide for PEM conversion, Railway variables, and troubleshooting.

Authentication

Every management request uses the token you set in API_TOKEN. Short-lived pass download URLs are the one exception: their random ID is the credential.

HTTP 
Authorization: Bearer YOUR_API_TOKEN
Content-Type: application/json
Keep it server-side. Treat the API token like a password. Pocketful stores it locally on your device; don’t put it in pass fields or commit it to the repository.

Create a pass

Send a pass specification to POST /api/passes. Artwork is a map of Wallet image names to base64-encoded PNG data.

1. Define the pass

pass.json 
{
  "style": "generic",
  "description": "Studio membership",
  "organizationName": "Northstar Studio",
  "logoText": "NORTHSTAR",
  "colors": {
    "backgroundColor": "#171923",
    "foregroundColor": "#FFFFFF"
  },
  "fields": {
    "primary": [
      { "key": "member", "label": "MEMBER", "value": "Ada Lovelace" }
    ]
  },
  "barcodes": [
    { "format": "PKBarcodeFormatQR", "message": "member_001" }
  ],
  "images": {
    "icon": "BASE64_PNG_DATA",
    "icon@2x": "BASE64_PNG_DATA"
  }
}

2. Send it

Shell 
curl https://your-pocketful-server.example/api/passes \
  --request POST \
  --header "Authorization: Bearer $API_TOKEN" \
  --header "Content-Type: application/json" \
  --data @pass.json

3. Use the download URL

201 JSON 
{
  "id": "d4f8…",
  "url": "https://…/api/passes/d4f8…",
  "expiresAt": "2026-08-05T18:15:00.000Z"
}

Download links expire after 15 minutes by default. Set "updatable": true to retain a pass and receive a stable serial number for over-the-air updates.

Endpoints

The management API is small by design. Apple’s separate /v1 web-service routes are called by iOS automatically.

GET /healthz Check service health
POST /api/passes Create and sign a pass
GET /api/passes/:id Download a short-lived pass
GET /api/passes List updatable passes
GET /api/passes/:serial/spec Read a stored pass spec
PUT /api/passes/:serial Replace and push an update
POST /api/passes/:serial/download Mint a fresh download URL
DELETE /api/passes/:serial Delete a stored pass

Need every supported pass field? The canonical schema lives in server/src/types.ts.
